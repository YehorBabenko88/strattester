# Bounded ticker acquisition source design

Base Data98 da80e53, not experimental schema3. Preserve the 15-field original Grid204897 delta allowlist, but only Math validates funding numeric domains. Twelve other bounded JSON scalar values remain explicitly UNVALIDATED. Omitted fields retain values AND original observation clocks; present null/empty removes known value/proof; an explicitly repeated value gets new clocks. Reconnect clears epoch values/proofs. Invalid funding rejects the entire candidate without partial mutation.

Reuse public_connection, decode_frame, RawCaptureRecorder/rawv2 and the single supplied sink; no SQL/normalized table/writer. A bounded ticker wrapper is needed because the existing trade/book wrappers hardcode different topics and engines. One physical run is limited to four frames and one instrument; caller may construct a new owner for reconnect, never retry uncertain storage or callbacks.

Before raw store, append a source-bound original occurrence envelope to the existing SegmentWAL. ACK requires literal True and exact delivery/source/connection/frame hash binding before WAL ACK and state publication. Unknown store/consumer/cancellation retains pending WAL and poisons owner. Recovery is idempotent inspection only: original clocks/epoch remain UNKNOWN and RECONCILIATION_REQUIRED; no automatic new raw observation or freshening. New acquisition refuses pending recovery. No normalized SQL idempotency or exactly-once publication is claimed.

Original synthetic socket fixture obligations are retained in provenance. Scope uses bounded fake transports/stores and real temporary SegmentWAL only. Actual provider/PG/native/process/clock synchronization/source authentication/coverage/PIT are NOT_RUN or UNKNOWN. No managed route or live enablement.


Implemented recovery: the existing recorder sink boundary journals exact already-generated observation_bytes/payload_bytes before same sink.store_capture. A shared validate_capture_receipt predicate validates original bytes and exact durable sink facts. Fresh owner recover() validates the entire bounded source/chain/delivery binding before side effects, re-submits exact raw observations through the same idempotent CaptureStore path and requires original-key consumer ACK with RECOVERY_UNKNOWN_NOT_FRESH. No new raw clock/UUID is generated, no recovered state becomes fresh. Consumer publication uses original_epoch_snapshot_seen, never a current fresh_snapshot flag. All raw and consumer records are checkpointed together by SegmentWAL.ack_prefix after all receipts match; missing prefixes and checkpoint faults refuse. Single-record ack semantics remain unchanged. This assumes exclusive caller ownership of WAL/sink and idempotent consumer handling of the exact occurrence hash; native ownership/fsync/physical durability remain unqualified.

Safety differences from the historical mixed collector: public linear endpoint only; explicit instrument and exact subscription args, one physical epoch and up to4 frames; no automatic reconnect/backoff retry of unknown effects; pre-ACK market frames fail closed with raw gap rather than legacy buffering; strict provider integer millisecond ts, no wall-clock fallback/future tolerance; invalid funding rejects the full candidate and stops epoch rather than publishing arbitrary scalars. Present-null/empty explicitly becomes unknown per new master (historical source ignored null). Original max_ticker_age_ms policy/automatic retry, shared multi-instrument ACK buffering and snapshot throttling remain unported obligations; source retained, no claim whole MicrostructureCollector retirement. No extra clock unit arithmetic: acquisition requires an explicit process millisecond clock provider for run; recovery needs none.

Validation: 37 new scoped tests plus existing488 cases (525 total) source PASS before final artifact build. Tests use real temporary SegmentWAL and synthetic socket/fake sink only. No actual provider/network/Postgres/native process or hosted acceptance.

Managed calls reuse admission.startup_identity. Current grant/identity is checked around recorder WAL/store boundaries, receives, consumer callback and prefix ACK. Revocation during WAL append prevents the underlying store; revocation during consumer callback retains all occurrence WAL and blocks state commit. Known cancellation with no uncertain pending effect records a durable cancelled disconnect; unknown raw/consumer outcome emits no extra retry/control write.
