## Intent and scope
Complete software validation of the existing G0 observation v2 contract without collecting physical target facts or granting admission. Preserve all ten real VM fact groups as NOT_COLLECTED/null. Do not operate LS5/PC4, launch G1, run trading, merge main, connect databases or execute the physical collector.

## Existing behavior and gap
The collector already distinguishes OBSERVED/EMPTY/MISSING/UNAVAILABLE, with NOT_COLLECTED reserved for manifests. The signature verifier binds externally pinned owner/provider identities and distinct keys, but always blocks admission. The manifest inspector checks fact envelopes but treats command captures and descriptive policy as untrusted arbitrary JSON. Private capture controls, identity and external provisioning templates are currently documentary, not a connected validated contract.

## Approach
Extend the existing bounded, pinned, read-only inspection path. Validate a versioned target qualification contract connecting the target-specific manifest, external policy/trust identities, signed binding receipt and private capture record hashes. Do not implement a physical runner or target admission.

Alternatives considered: documentation-only updates would leave machine-checkable gaps; a capture runner would require actual VM authorization and independently enforced controls absent here. Neither satisfies the present software-only boundary as directly.

## Contract
- Keep observation v2 cardinality separate from required-field and empty_allowed policy. Reject malformed state/value pairs, partial failures presented as success and inconsistent collector/fact states.
- Require external pins and explicit owner/provider roles; retain separate authority identities and keys, fixture-key exclusion, revocation and validity windows. Self-reported policy never supplies trust.
- Check identity binding across provider VM/generation, guest identity, owner, release/source/tree/package/commands, tool roster, private roots and receipt hashes. Never infer a real identity from software fixtures.
- Validate capture records with exact field sets and strict integer/boolean types; timestamps, exit status, timeout, truncation, combined output bounds, free-space floor and independently evidenced enforcement must agree. Missing enforcement remains blocked.
- Raw streams remain private. Public inspection returns only bounded status/reason/hash information, never raw identities, paths, arguments, provider diagnostics or secrets. No referenced evidence path is opened.
- Preserve NOT_COLLECTED/null real templates; synthetic positive fixtures are explicitly software-only. No successful software verification can authorize G0/G1, cleanup, deployment or trading.

## Verification and deliverables
Use failing adversarial tests before implementation. Add negative cases independently of production field constants: identity/policy substitution, shared or fixture authorities, stale/revoked trust, malformed capture types, boundary overrun, partial/truncated output, missing private binding, contradictory target/release hashes and leaked raw fields. Retain existing mocked PowerShell 5.1/7 tests; never invoke actual inventory providers.

Run relevant test suites and required repository checks; inspect exact-commit CI after push. Open a Draft PR based on the source PR branch so the qualification delta remains reviewable. Record exact source HEAD/tree, commands and raw results, CI URLs/status, SHA256 evidence inventory and P0/P1/P2 findings. Report unavailable checks explicitly.

## Unresolved external prerequisites
VM selection, owner/provider authority provisioning, target identity, private storage/ACL/encryption, snapshot/rollback, enforced capture boundary and physical observations are NOT_COLLECTED or unverified. Durable replay/admission remain blockers. Software changes must not claim to resolve them.
