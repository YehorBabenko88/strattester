# Historical research through one Math revision

The history-reference-pins.json file pins both APIs to one Math commit/tree.
`JointMathClient` verifies that checkout and Python executable, snapshots committed
Python/JS dependencies, verifies a separately pinned Node executable and executes
both engines from that immutable temporary source. Subsequent source/runtime tampering
fails closed. No scientific engine is imported from another checkout or fetched at runtime.

`compose(dataset, expected_pin, decision_ms, train_count, train_end_ms, graph)`
admits the Grid v1.1 envelope, selects a contiguous available prefix and delegates
historical forecasting and scientific composition to Math. Scientific source nodes
cannot be injected. Event times remain event times, publication delays remain delays.
Outputs include the full original row provenance and the single Math source manifest.
CLI: scripts/run_history_composition.py. Operator pins include dataset ID/fingerprint,
Math commit/tree, python_sha256, node_executable and node_sha256. They are not accepted
as evidence of source authenticity merely because the dataset contains matching strings.

`grid_math_history.replay` retains frozen training/validation selection and OOS accounting
with cash, fees, slippage, perpetual funding or explicit spot non-applicability. Delayed
features whose one-minute forecast horizon has elapsed are skipped. Synthetic checks
exercise costs, funding sign, insufficient cash, non-overlapping positions, delayed
publication, source mismatch and the causal prefix. Scientific comparisons remain
descriptive arrays; they are not OOS profitability certificates or automatic trading signals.

Source admission for real Bybit PostgreSQL snapshots remains BLOCKED until owner-provisioned
authenticated per-revision receipts prove actual first availability, completeness, clock
semantics, coverage, units and revision origin. A hash alone does not establish those facts.
No live database connection, trading, deployment or PR merge occurs in this workflow.
