## Producer-issued export adapter proposal (no physical mutation)

Fail closed unless a producer-owned export provides exact code/schema/source identity; producer epoch; exchange/market/symbol/timeframe; immutable source snapshot IDs; origin+knowledge cutoff; event completeness watermark per source; recorded first_available_ns and every revision valid-from; immutable canonical content SHA256+counts+ordered ranges+gap/quality/eligible/completeness results; coherent cut across all source snapshots; producer attestation bound to complete manifest bytes and trusted producer key/identity. Consumer must not manufacture missing facts from file mtime, latest candle timestamp, leader lease, or consumer_watermarks. Producer lease epoch can fence publication but is not data-revision epoch.

Export should use producer transaction/repeatable-read plus versioned immutable records or producer-frozen export; copying unrelated live tables in separate transactions is insufficient. Consumer reads immutable export only, verifies schema/manifest signature/hash/ranges/counts/revisions/cutoff/epoch first, then admits Snapshot. No direct production read is authorized until exact source schema and safe read-only URI/role confirmed. No historic availability retrofit is possible from latest-state candles alone.

Independent contract cases required: missing/replayed epoch; forged producer; mismatched manifests; partial sources; stale completeness watermark; overwritten revisions; event available after origin; schema changes; gaps/duplicates; quality UNKNOWN; eligible false; partial publication; concurrent producer cut changes; hash/path substitution. These tests can use small temporary synthetic exports and databases under work; PASS means contract enforcement, never production readiness.
