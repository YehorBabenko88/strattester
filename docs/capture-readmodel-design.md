Cursor contract is deliberately inspection-only: complete_prefix=False, resume_is_lossless=False, inspection_only=True on EVERY page, including empty pages. Generated ordinals are allocated before commit and may be reserved/cached or rolled back. A later committed higher ordinal can be visible before a lower uncommitted ordinal; resuming after the higher value can miss the lower row. No complete-prefix or durable resume guarantee is offered. Modeled concurrent commit, rollback and reserved-range tests expose this limitation rather than treating holes as provider loss. A future lossless feed requires an independently qualified allocation/commit fence and actual PostgreSQL concurrency fault tests before changing these flags. Current runtime does not implement that fence. Schema catalog/identity/cache verification is also pending; the operator metadata tag is not independent catalog proof.
