## Findings

1. **[P2] Circular label control may leave every label unchanged.** `mwi_offline/evaluation.py:86-94` sets shift=floor(n/3), without checking changed assignments. For 27 episodes with labels repeating BREAKOUT,BOUNCE,TIMEOUT, shift=9 returns exactly the original labels. Periodic artificial data is the input domain here, so a control that retains the entire target association can misleadingly look predictive. `tests/test_evaluation.py:test_block_control_preserves_label_counts` covers n31 only. Use a predeclared block permutation with a changed-assignment/support check; report CONTROL_UNINFORMATIVE when no useful displacement is possible. Do not require arbitrary control performance deterioration as a success gate.

2. **[P2] The purported graph permutation also scrambles node-only information.** `mwi_offline/evaluation.py:127-131` permutes all graph columns after baseline. The node-only control at `features.py:127` uses the first two and last of those same columns (nearest level, confluence, node count). Consequently graph_permutation vs graph cannot isolate graph-edge information: any difference can come from destroying the extra node summaries. Preserve the node-only columns and shuffle only mean_degree/mean_edge_distance_atr, or rename/document this as permutation of all added node+edge features and add a separate edge-only control. The direct graph-vs-node_only ablation remains useful.

3. **[P2] Test labels need an explicit observation-as-of boundary.** `mwi_offline/evaluation.py:74-79` checks maturity+embargo only for train/calibration; test accepts any non-None label_available, even beyond test_end. A provided sample row cutoff7900,label_end8120,label_available8150 is accepted in split test_end8000. In this synthetic static offline run the bars may legitimately contain that future outcome, so this is not training leakage. But the report's test_end cannot be read as a completed observation horizon, and external delayed-availability snapshots have no declared evaluation_as_of. Add an independent evaluation_as_of from the snapshot observation boundary and exclude/report unmatured test outcomes, or explicitly record observation_end=max(label_end,label_available) and distinguish it from decision-window test_end. Readiness should not imply all outcomes were available by the stated test window end.
